Log Metadata Form & JSON Management

表单填Key-Value → 生成/追加 dm-log.json → 保存至工作目录

表单字段（基于需求中的 JSON 示例）

文本输入
  • DMP版本号
  • DMP版本日期
  • 方案定稿日期
  • 临床监查方名称
  • 统计分析方名称
  • 版本修订记录
  • 撰写者/修订者
单选/下拉
  • 项目类型：药物/器械
  • 数据采集模式：EDC/PDC
  • 是否使用登记系统
  • 是否使用随机系统
  • 是否涉及外部数据
  • 是否涉及医学编码
  • 是否有中期分析
  • 是否需要预递交
  • ...
条件展开
  • EDC系统供应商（EDC时显示）
  • 随机系统供应商（随机时显示）
  • 设计的外部数据类型（外部数据时显示）
  • 阶段性分析目的和阶段要求
  • 项目质量控制等级/模板

核心逻辑：新建 vs 追加版本

首次创建
工作目录中 无 dm-log.json
↓
表单提交 → 创建新文件
↓
dm-log.json = [{ entry #1 }]
追加版本
工作目录中 已有 dm-log.json
↓
读取现有内容 → 追加新条目
↓
dm-log.json = [{...}, {entry #2}]

API 设计

GET /api/log/current
  → 返回 dm-log.json 最新一条数据（用于回填表单/展示当前版本）

POST /api/log/save
  → 提交表单数据
  → 如果 dm-log.json 存在，append 到数组末尾
  → 如果不存在，创建新文件写入 [{...}]
  → 返回保存后的完整 JSON
注意： 前端表单字段定义应可配置（从 protocol-to-dmp skill 的 DMP非固定内容清单.xlsx 派生出表单字段列表），而非硬编码前端代码，方便后续 checklist 更新后表单自动适配。
