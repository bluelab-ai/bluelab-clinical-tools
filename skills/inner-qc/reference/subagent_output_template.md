# Subagent QC 输出模板（inner-qc v2.0 — 原表标注 + 核查项总览 + 四级问题分级）

**每个 subagent 必须严格按照此模板输出每张表的人读 markdown，不得增删或移动元数据行。**

> **产物**（每张表两份，同一 subagent 一轮内完成）：
> - 机器读 JSON：`qc_output/qc_<编号>.json` — 由 `qc_lib.Issues.to_json` 自动产出，供 `build_reports.py` 跨表合并（权威源）
> - 人读 markdown：`qc_output/qc_<编号>.md` — 按本模板渲染；元数据与 JSON 字段对齐
---

## 输出文件格式

```
##META_TABLE: <表格完整标题>
##META_TYPE: <表型>
##META_ANALYSIS_SET: <FAS|ITT|mITT|PPS|SS|随机化人群|->
##META_CONCLUSION: PASS|CRITICAL|MAJOR|MINOR|SUGGESTION

## 核查项总览
（已核查无误的数据 + 异常 + 待人工的统计；即使全 PASS 也必须有）

|------|---------|------|------|-------|
| R-XXX 简述 | n | n | n | n |

> - 原表行/列结构必须与原始表格一致（包括表头、分组、统计量行）

> - 存在差异的数值标注 `❌`，并在「发现的问题」中对应说明
> - 表内一致性检查（如 n+missing=N、分类之和=总例数）统一在表末标注

## 严格规则

### 1. 元数据行（必须放在文件最前面，每行独立，不可省略）

```
##META_TABLE: 表 14.4.1 各组疗效分级
##META_TYPE: 标准定性定量表
##META_ANALYSIS_SET: FAS
##META_CONCLUSION: MAJOR
```

- `##META_TABLE:` 后跟表格完整标题，与 `tables_output/<编号>-<类型>-<标题>-<分析集>.xlsx` 文件名中的标题字段一致
- `##META_TYPE:` 后跟表型，取值范围：
  `标准定性定量表 / 事件表 / 交叉表 / 病例分布表 / 入组病例表 / 人群划分表 / 协方差 / other`
- `##META_ANALYSIS_SET:` 后跟 `FAS / ITT / mITT / PPS / SS / 随机化人群 / -`（与文件名末段一致，只填纯 acronym，禁止 `FAS人群`/`ITT集` 这类带后缀的写法；`mITT` 首字母小写）
  - `随机化人群` 用于 人群划分表 / 病例分布表 / 入组病例表（入组人群）
  - `-` 表示表题与父节都未声明分析集——**允许，不再视为错误**，正常核查即可
- `##META_CONCLUSION:` 后只能是 `PASS / CRITICAL / MAJOR / MINOR / SUGGESTION` 之一，不带后缀
  - `PASS` = 没有任何硬级别问题；"待人工"项可以存在但不影响 PASS 判定（通过 JSON 的 `pending` 字段反映）
  - 其余 = 取所有发现问题的**最高级别**
  - **必须与 `qc_<编号>.json` 中 `conclusion` 字段完全一致**
- 元数据行之间**不能有空行**，必须连续放在文件最开头
- **inner-qc 不含 `##META_LISTING`**（无 Listing 交叉核查）；勿照抄交叉核查模板

### 2. 核查项总览（已核查无误的数据汇总）

**目的**：把"实际跑了哪些核查、各跑了几个、结果分布如何"显式列出。否则人读者无法区分"全部通过"和"根本没核查"——这是 PASS 表最容易被滥用的盲区。

| 规则 | 检查项数 | 通过 | 异常 | 待人工 |
|------|---------|------|------|-------|
| R-006 例数+缺失=N | 6 | 5 | 0 | 1 |
| R-007 五数次序 | 3 | 3 | 0 | 0 |
| R-016 Σ%≈100 | 4 | 4 | 0 | 0 |
| R-017 %=n/N | 24 | 23 | 1 | 0 |
| R-025 类别人数和=总例数 | 4 | 4 | 0 | 0 |
| R-009 表头 N ≤ baseline | 3 | 3 | 0 | 0 |
| R-028 表题分析集 ↔ 合计 | 1 | 1 | 0 | 0 |
| R-036 表头 ⊆ 表题分析集 | 1 | 1 | 0 | 0 |
| **合计** | **46** | **44** | **1** | **1** |

- "检查项数" = 实际跑核查的单元格/位置数；**缺数据 / 取不到值已剔除**（与"缺数据静默跳过 ≠ 通过"原则保持一致）
- "异常" 数应等于「发现的问题」节中**硬级别问题数**（CRITICAL/MAJOR/MINOR/SUGGESTION 之和）
- "待人工" 数应与 JSON 的 `pending` 字段一致
- 仅列出该表型实际跑过的规则；未触发的规则（如本表无连续变量则不列 R-007）不写
- 最后一行写"**合计**"，便于一眼读出本表核查规模

### 3. 原表（核查标注）

- **原表（含核查标注）是本文件的主体，无论结论是PASS/MAJOR/CRITICAL，原表的行数、列数、表头层级必须与原始xlsx完全一致——一行都不能省与合并
- **标注方式**：在原表每个**被核查的**数值后加 ✅，有差异的加 ❌
- **原表结构必须与原始 xlsx 一致**（行列、表头、分组、统计量行）
- **表内一致性检查**（n+missing=N、Σ%≈100、min≤Q1≤中位≤Q3≤max 等）统一在表末追加一行 ✅ 概括，每组一格
- **多截面/多子表**的表，**逐截面搬上来**并各自标注，不可合并简化

**分类变量示例**（标准定性定量表 / 事件表）：

| 指标 / 类别 | 试验组(N=50) | 对照组(N=48) | 合计(N=98) |
|------------|-------------|-------------|------------|
| 疗效·CR | 24(48.0%) ✅ | 22(45.8%) ✅ | 46(46.9%) ✅ |
| 疗效·PR | 16(32.0%) ✅ | 14(29.2%) ✅ | 30(30.6%) ✅ |
| 疗效·SD | 10(20.0%) ✅ | 12(25.0%) ❌ | 22(22.4%) ✅ |
| ✅ Σn = N | ✅ | ✅ | ✅ |
| ✅ Σ% ≈ 100 | ✅ | ✅ | ✅ |
| ✅ % = n/N | ✅ | ❌ | ✅ |

**分类变量示例**（标准定性定量表 / 事件表）（错误较多版）：

| 指标 / 类别 | 试验组(N=40) | 对照组(N=38) | 合计(N=78) |
|------------|-------------|-------------|------------|
| 疗效·CR | 24(48.0%) ❌ | 22(45.8%) ❌ | 46(46.9%) ❌ |
| 疗效·PR | 16(32.0%) ❌ | 14(29.2%) ❌ | 30(30.6%) ❌ |
| 疗效·SD | 10(20.0%) ❌ | 12(25.0%) ❌ | 22(22.4%) ❌ |
| ✅ Σn = N | ❌ | ❌ | ❌ |
| ✅ Σ% ≈ 100 | ✅ | ✅ | ✅ |
| ✅ % = n/N | ❌ | ❌ | ❌ |

**连续变量示例**（年龄、生命体征等）：

| 统计量 | 试验组(N=50) | 对照组(N=48) | 合计(N=98) |
|--------|-------------|-------------|------------|
| 例数(缺失) | 49(1) ✅ | 47(1) ✅ | 96(2) ✅ |
| 均值(SD) | 56.2(8.1) ✅ | 55.7(7.9) ✅ | 56.0(8.0) ✅ |
| 中位数 | 55.0 ✅ | 56.0 ✅ | 55.5 ✅ |
| Q1, Q3 | 50.0, 62.0 ✅ | 51.0, 61.0 ✅ | 50.5, 61.5 ✅ |
| Min, Max | 38, 78 ✅ | 40, 75 ✅ | 38, 78 ✅ |
| ✅ 例数+缺失=N | ✅ | ✅ | ✅ |
| ✅ min≤Q1≤中位≤Q3≤max | ✅ | ✅ | ✅ |

**标注规则**：
- 不被核查的单元格（组名、单位说明、脚注引用等）**不标 ✅**
- 缺数据 / 取不到值的单元格**不标 ❌**（保持"静默跳过 ≠ 异常"）
- 协方差表数值不重算 → 数值统一标 `—（SAS 直出，不核查）`，仅对表题分析集打 ✅/❌

### 4. 发现的问题

| 编号 | 规则 | 分级 | 位置 | 期望 | 实际 | 说明 |
|------|------|------|------|------|------|------|
| 1 | R-017 | Major | 疗效·SD·对照组 | 20.8% | 25.0% | 印刷 25.0%，应为 10/48×100=20.8%；差 4.2pp，疑似 SD 行人数/百分比串位 |

- "规则" 列填规则编号（如 `R-017`）或无编号规则名（如 `合计一致性`）
- "分级" 取 `Critical / Major / Minor / Suggestion / 待人工` 之一；首字母大写（人读规约）；对应 JSON 中的 `CRITICAL/MAJOR/MINOR/SUGGESTION/待人工`
- "位置" 用 `指标·组别` 或 `表头·组别` 等可定位的字符串，与 JSON 的 `where` 字段保持一致
- "期望" / "实际" 必须填具体数字或具体字符串，禁止写"应一致 / 不一致 / 有偏差"
- 若未发现任何问题，整节写：**未发现问题。**

## 反例（禁止出现）

```
❌ 综合结论：PASS                          （结论必须放 ##META_CONCLUSION）
❌ ##META_CONCLUSION: WARN                 （旧值，已废弃）
❌ ##META_CONCLUSION: FAIL                 （旧值，已废弃）
❌ ##META_CONCLUSION: PASS — 全部通过      （后缀不允许）
❌ ##META_CONCLUSION: PASS 但「发现的问题」列出了 Major
❌ 缺少 ##META_TYPE                        （inner-qc 强制字段，build_reports 依赖它做表型分布）
❌ 缺少 ##META_ANALYSIS_SET                （即使本表无声明也要写 —）
❌ 含 ##META_LISTING:                      （inner-qc 无 Listing，禁用）
❌ 元数据行不在文件最开头
❌ 元数据行之间夹杂空行或正文
❌ 缺「核查项总览」章节                    （PASS 表更要有：否则"全通过"与"没核查"无法区分）
❌ 「核查项总览」合计的"异常"数 ≠ 「发现的问题」表行数
❌ 缺「原表（核查标注）」章节
❌ 用独立核查清单代替原表标注              （必须搬原表）
❌ 原表结构与原始 xlsx 不一致              （行列、表头、分组、多截面必须保留）
❌ PASS 表只写"未发现问题"不搬原表
❌ 在缺数据 / 取不到值的单元格标 ⚠️       （静默跳过 ≠ 异常）
❌ 「发现的问题」表少「规则」「位置」「期望」「实际」任一列
❌ 「期望」/「实际」写"应一致 / 不一致 / 有偏差"等非具体值
❌ markdown 的 ##META_CONCLUSION 与同表 qc_<编号>.json 的 conclusion 不一致
```
