# Subagent QC 输出模板（v4.0 — 原表标注 + 四级问题分级）

**每个 subagent 必须严格按照此模板输出，不得增删或移动元数据行。**

---

## 输出文件格式

```
##META_TABLE: <表格名称>
##META_CONCLUSION: PASS|CRITICAL|MAJOR|MINOR|SUGGESTION
##META_LISTING: <清单名称>|<清单人群>

### <表格名称>

| 参考清单 | 清单人群 |
|----------|----------|
| <清单名称> | <清单人群> |

## 原表（核查标注）

将原表格完整搬上来，在每个被核查的数值旁标注 ✅（通过）或 ⚠️（异常）。

> **标注规则：**
> - 原表行/列结构必须与原始表格一致（包括表头、分组、统计量行）
> - 每个被核查的数值后标注 `✅<sup>1</sup>`，脚注说明来源
> - 存在差异的数值标注 `⚠️`，并在「发现的问题」中对应说明
> - 表内一致性检查（如 n+missing=N、分类之和=总例数）统一在表末标注

```markdown
**表 X.X.X 表格标题**（分析集，N=xxx）

| 指标 | 试验组(N=xx) | 对照组(N=xx) | 合计(N=xx) |
|------|-------------|-------------|------------|
| 分类A-有 | xx(x.x%) ✅ | xx(x.x%) ✅ | xx(x.x%) ✅ |
| 分类A-无 | xx(x.x%) ✅ | xx(x.x%) ✅ | xx(x.x%) ✅ |
| 分类B-有 | xx(x.x%) ✅ | xx(x.x%) ✅ | xx(x.x%) ✅ |
| ... | ... | ... | ... |
| ✅ 分类之和=N | ✅ | ✅ | ✅ |
| ✅ 百分比=计数/N | ✅ | ✅ | ✅ |

> ✅<sup>1</sup> 人数/百分比与 Listing XX 反推一致，差值 ≤0.1%
> ✅<sup>2</sup> 统计量与 Listing 反推一致（均值/SD/中位数/Q1/Q3/min/max）
```

**统计量表标注示例（年龄等连续变量）：**

| 统计量 | 试验组(N=xx) | 对照组(N=xx) | 合计(N=xx) |
|--------|-------------|-------------|------------|
| 例数(缺失) | xx(0) ✅ | xx(0) ✅ | xx(0) ✅ |
| 均值(SD) | xx.x(xx.x) ✅ | xx.x(xx.x) ✅ | xx.x(xx.x) ✅ |
| 中位数 | xx.x ✅ | xx.x ✅ | xx.x ✅ |
| Q1, Q3 | xx.x, xx.x ✅ | xx.x, xx.x ✅ | xx.x, xx.x ✅ |
| Min, Max | xx, xx ✅ | xx, xx ✅ | xx, xx ✅ |
| ✅ min≤Q1≤中位数≤Q3≤max | ✅ | ✅ | ✅ |

（原表格可能有多个截面/子表，全部逐一搬上来并标注）

## 发现的问题

| 编号 | 分级 | 问题描述 | 说明 |
|------|------|----------|------|
| 1 | Major | 分析集不一致 | Table标注FAS(N=15)，Listing为SS(N=15)，虽人数一致但标注不同 |
| ... | ... | ... | ... |

（若未发现任何问题，此行写"**未发现问题。**"）

## 问题详情

<仅描述与问题相关的具体数值和受试者编号。无问题则写"无。">
```

## 严格规则

### 1. 元数据行（必须放在文件最前面，每行独立，不可省略）

```
##META_TABLE: 人口学信息（FAS）
##META_CONCLUSION: MAJOR
##META_LISTING: 人口学信息清单（FAS）|FAS
```

- `##META_TABLE:` 后直接跟表格名称，与映射表中的名称完全一致
- `##META_CONCLUSION:` 后只能是 `PASS`、`CRITICAL`、`MAJOR`、`MINOR`、`SUGGESTION` 之一，不能带任何后缀
  - `PASS` = 未发现任何问题
  - `CRITICAL`/`MAJOR`/`MINOR`/`SUGGESTION` = 取所有发现问题的**最高级别**
- `##META_LISTING:` 后跟 `清单名称|清单人群`，多个清单用 `||` 分隔
- 元数据行之间不能有空行，必须连续放在文件最开头

### 2. 问题分级标准

| 级别 | 定义 | 示例 |
|------|------|------|
| **Critical** | 可能影响主要结论、分析集、主要终点、安全性结论或监管判断 | 主要终点人数无法从Listing反推；P值和结论不一致；SS归组错误；死亡人数前后不一致 |
| **Major** | 可能影响报告质量、可追溯性或审评理解，但不一定直接改变结论 | SAP预设敏感性分析未报告；Table无对应Listing；表题分析集与分母不一致；人群划分与Listing不符 |
| **Minor** | 格式、表号、脚注、版本、编码等问题 | 表号引用错误；表名重复；N标注格式不统一；百分比四舍五入不一致（≤0.2%） |
| **Suggestion** | 不构成错误，但建议改得更清楚 | 补充特殊受试者脚注；建议补充缺失清单；措辞统一建议 |

### 3. 原表标注与问题分离

- **所有 pair（含 PASS）必须将原表格搬上来并标注核查结果**，不可仅写「全部一致」
- **标注方式**：在原表每个数值后加 ✅，有差异的加 ⚠️
- **原表结构**必须与原始表格一致（行列结构、表头、分组、统计量），有多个截面的逐截面搬上来
- **表内一致性检查**（n+missing=N、分类之和=总例数、min≤Q1≤中位数≤Q3≤max 等）统一在表末标注
- PASS 的 pair 全表 ✅，发现的问题写「未发现问题」
- 有问题的 pair 在「发现的问题」表中列出所有问题，每行标注级别，META_CONCLUSION 取最高级别
- 问题说明列必须包含具体数值（Table=X, Listing=Y）

### 4. 反例（禁止出现）

```
❌ 综合结论: **PASS**
❌ **结论**: FAIL — 总例次数不一致
❌ 结论行缺失
❌ 元数据行不在文件最开头
❌ ##META_CONCLUSION: FAIL — 有差异   （应为 FAIL）
❌ ##META_CONCLUSION: WARNING          （应为 WARN）
❌ ##META_CONCLUSION: WARN             （旧格式，已废弃）
❌ META_CONCLUSION 取 PASS 但问题表列出了问题
❌ 问题表缺少"分级"列
❌ 缺少「原表（核查标注）」章节 — 没有搬原表上来
❌ 用独立核查清单代替原表标注 — 必须把原表搬上来、在原表数值上标 ✅/⚠️
❌ 原表结构与原始表格不一致 — 行列、表头、分组必须一致
❌ PASS 的 pair 只写「未发现问题」不搬原表
```
